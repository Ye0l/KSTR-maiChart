# maiChart

SvelteKit + SVG로 만든 가벼운 Simai(maimai) 차트 뷰어. 차트를 무음 자동 재생하며 **게임 뷰 / 평면 뷰 / Isometric** 세 가지 시점으로 볼 수 있고, 모바일에서도 그대로 쓸 수 있습니다.

## 주요 기능

- **곡 찾기**: 좌측 패널에서 곡명·ID 검색, **레벨**(maimai 표기 `13` / `13+`)과 **버전** 필터. 목록을 누르면 바로 열리고, 레벨 필터 중에는 해당 난이도로 엽니다.
- **난이도 칩**: BASIC~Re:MASTER를 게임 색으로 표시하며 상단바에 현재 난이도 배지가 붙습니다.
- **세 가지 뷰** (상단 토글, 동시에 여러 개 가능)
  - **게임 뷰**: 실제 화면과 같은 원형 판. SLIDE는 maimai식 화살표 트랙으로 그리고 별이 지나간 화살표는 사라집니다.
  - **평면 뷰**: 왼쪽부터 1~8 레인, 위에서 아래로 진행. 박자마다 가로선(마디 첫 박은 진하게)이 노트와 같은 속도로 내려옵니다. SLIDE는 시작·대기·끝만 연결합니다. TOUCH는 센서에 대응하는 레인에, 중앙 C는 4/5 레인 사이에 표시합니다.
  - **Isometric**: 판을 회전 없이 뒤로만 기울여(인게임처럼 12시 양옆이 1·8번) 눕히고 노트가 판과 평행한 원판으로 수직 하강합니다. 높이 = 판정까지 남은 시간.
- **재생바**: 노트 타입별(TAP·HOLD / SLIDE / BREAK / TOUCH) **밀도 그래프**, 진행 시크바, 재생 속도, 뷰별 노트·터치 배속 패널.
- **탐색**
  - 휠: 아래로 앞, 위로 뒤
  - PC 클릭-드래그: 노트를 잡듯이 아래로 끌면 앞, 위로 끌면 뒤 (240px = 1초)
  - 모바일 스와이프: 노트를 잡듯이 아래로 내리면 앞, 위로 올리면 뒤, 네이티브 관성 유지 (240px = 1초)
  - 키보드(탐색 영역 포커스): ↓/PageDown/Space 앞, ↑/PageUp/Shift+Space 뒤, Home/End 처음·끝
  - 밀도 그래프를 누르거나 끌어서 해당 위치로 이동
  - 플레이 화면 **탭/클릭**: 재생·일시정지 전환. 직접 탐색하면 자동 재생은 멈춥니다.

## 화면 구성

- 상단바는 고정입니다. 좌측 차트/정보 패널과 하단 재생바는 버튼으로 접을 수 있습니다.
- 여러 뷰는 데스크톱에서 좌우, 모바일에서 위아래로 배치합니다. 켠 순서대로 표시하며, 껐다 다시 켜면 마지막에 붙습니다.
- 재생 위치·재생 속도는 모든 뷰가 공유합니다. 노트/터치 배속은 뷰마다 따로이며 1.0~10.0(0.25 단위), 표시 시간은 `2000 / 배속` ms입니다. 기본값은 게임 뷰 6, 평면·Isometric 2이고 뷰별로 `localStorage`에 저장합니다(예전 공통 배속 저장값은 각 뷰로 이전).
- 모바일에서는 패널이 하단 시트로 열립니다. 바깥 영역이나 Escape로 닫습니다.
- 플레이 화면이 스크롤을 받아 확대 후 되돌리기 어렵기 때문에 페이지 확대·축소(핀치, 더블탭, 트랙패드 핀치/Ctrl+휠)를 막습니다.
- **누를 위치 강조**: 모든 뷰에서 TAP·HOLD 시작·별을 칠 때와 SLIDE가 끝날 때(판정 순간) 해당 버튼을 노트 색으로 강조합니다. TOUCH는 제외합니다. 버튼마다 가장 최근 입력이 남습니다. 잔상은 배속 패널에서 -1(없음)·0(판정 순간만)·1~16으로 고르고, 단위는 **노트**(기본, 동시치기는 1노트)와 **비트** 중에서 고릅니다. 노트 단위는 직전 N번의 입력 순간을 남기므로 잔상이 짧을수록 손을 빨리 옮겨야 한다는 뜻입니다. 기본값은 4노트이며 `localStorage`에 저장합니다.
- 노트 색: 단독 TAP/HOLD 분홍, 동시입력 노랑, TOUCH 민트, SLIDE 하늘, BREAK 주황(최우선), EX는 흰 테두리. HOLD 끝이나 SLIDE 트랙은 동시입력 수에 넣지 않습니다.

### Isometric 가독성 보조

- 넓은 패널에서도 낙하 공간이 남도록 캔버스 폭을 높이의 0.9배로 제한하고, 판은 아래쪽에 고정한 채 높이에 맞춰 낙하 거리를 늘립니다.
- 판의 센서 라벨은 숨기고 윤곽만 흐리게 둡니다.
- 노트가 떨어질 자리에 좁혀지는 **착지 표시**, 각 위치의 다음 노트와 착지 지점을 잇는 같은 색 **세로선**을 그립니다.
- 박자마다 흐린 **박자 링**(마디 첫 박은 조금 진하게)이 노트와 같은 속도로 내려옵니다.
- 노트 높이의 링은 노트 방향에서 가장 두껍고 밝으며, ±30°(양옆 버튼까지의 2/3)에서 기본 굵기로 돌아갑니다.
- SLIDE는 판 위의 화살표 트랙이 주 표현이고, 대기·진행 시간에 따른 높이의 경로는 흐린 선으로 함께 표시합니다.

## 실행

Node.js 22.18 이상과 pnpm이 필요합니다. 차트 데이터는 [`Maichart-Converts`](https://github.com/Neskol/Maichart-Converts) 서브모듈입니다.

```sh
git clone --recurse-submodules <this-repo>
# 이미 받았다면: git submodule update --init --recursive
pnpm install
pnpm dev --host 0.0.0.0
```

## 빌드와 GitHub Pages 배포

정적 사이트로 빌드합니다(`@sveltejs/adapter-static`). 빌드 때 곡 카탈로그는 `catalog.json`, 각 차트는 `charts/<번호>.txt`로 프리렌더하고, 브라우저가 이 파일들을 받아 그립니다. 곡 주소는 `?chart=<경로>` 쿼리라서 딥링크도 그대로 동작합니다.

```sh
pnpm build                                # build/ 에 출력
BASE_PATH=/KSTR-maiChart pnpm build       # Pages처럼 하위 경로에 올릴 때
```

`.github/workflows/pages.yml`이 서브모듈을 포함해 빌드하고 Pages에 배포합니다. **수동 실행 전용**이며 push로는 배포되지 않습니다.

1. 저장소 **Settings → Pages → Build and deployment → Source**를 **GitHub Actions**로 설정합니다.
2. Actions 탭에서 **Deploy to GitHub Pages**를 실행하거나 `gh workflow run pages.yml`을 실행합니다.

## 범위와 한계

- `maidata.txt`의 메타데이터와 난이도별 노트를 읽습니다. BPM·박자 분할 변경, 길이, SLIDE 대기시간을 해석합니다.
- TAP, HOLD, TOUCH, TOUCH HOLD, BREAK, EX, SLIDE 및 연결·분기 SLIDE를 표시합니다.
- 버튼 위치는 `simai_spatial_reference/spatial_reference.json`, B/E 센서 윤곽과 터치 위치는 공식 스킨을 측정한 `src/lib/sensor-layout.ts`를 사용합니다.
- SLIDE 경로와 구간별 이동은 시각화용 근사치이며 원본 게임과의 정밀 일치를 보장하지 않습니다.
- 박자 링은 4/4박을 가정하고 BPM이 바뀌는 지점부터 박을 다시 셉니다.
- 음원·판정·점수·입력 플레이는 없습니다. 미지원 표기는 정보 탭에 경고하고 건너뜁니다.
- 자켓 이미지는 아직 없습니다(차트 저장소에 포함되어 있지 않음).

## 검증

```sh
pnpm test    # 파서·경로·Isometric 헬퍼 단위 테스트와 저장소 전체 차트의 유한 시간/좌표 검사
pnpm check
pnpm build
```

Chromium을 설치하고 개발 서버(또는 빌드 결과를 정적 서버로 띄운 주소)를 연 뒤 `node --test tests/layout.test.mjs`로 패널 토글·뷰 전환·노트 이동·공통 색상·배속 저장·탭 재생·드래그 탐색·모바일 레이아웃을 검사합니다.
주소가 다르면 `VIEWER_URL=http://localhost:5174/ node --test tests/layout.test.mjs`처럼 지정합니다.
전체 차트 검사는 원본 재생과의 일치 검사가 아닙니다.
